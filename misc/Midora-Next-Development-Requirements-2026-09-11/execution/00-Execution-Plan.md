### 5.1 性能实验安全与可比性

- 基线优先沿用`9KX2 18 Million Notes.mid`、MIDI Out #23密集段及40万/百万选择；每次实际运行先确认用户授权样本与文件存在。合成数据覆盖空/1/10、稀疏/密集/跨页、极端Tick和重复，不能只拿大样本测平均。
- MIDI→Logical→SubVoice、冷首用与同位置重复要分别记；页面/视图/后台编译的工作集不可混成一条“命令耗时”。明确计时含不含准备、Selection、刷新及取消回收。
- 记录现有有限内存预算，新增buffer/索引/快照需写容量、增长规则、spill/淘汰/释放时机；预算通过实验冻结，不在本规划编造耗时或收益目标。
- 进程树内存接近9 GiB或出现持续失控趋势时停止探针，避免系统分页假死；**9 GiB是实验安全警戒，不是产品合格预算** 。同机内存余量不足时更早停止。
- UI不得同步冷解码/全轨计数；预览按现有共享路径、局部失效和有界后台任务实现，不恢复已经否决的多层陈旧Piano图像。
- 不主动改音频后端；R27试听及播放中UI相关实验仍需确认无所有权冲突、卡音/underrun回退。未做听感验收不写“声音完全通过”。

## 6. 状态、验收与返修方式

每个任务使用稳定ID，不因移批重编号。建议状态：`未开始 → 实施中 → 自动验证通过 → 待人工验收 → 验收通过`；另记`阻塞/返修中/暂缓`。工程任务无需人工检查的，可在其所属批次通过时关闭，不让用户逐个签字。

每轮交付时在主题文档追加一份记录：

| 字段 | 必填内容 |
|---|---|
| 本轮范围 | 批次、T-ID、R/D、完成与未完成项，实际基线/差异/证据文件。 |
| 自动验证 | 命令、环境、样本、结果；失败/未跑单列，不用计划替代结果。 |
| 性能 | 同条件前后对照、冷暖/资源峰值、取消与关闭释放；无测量则明确无数据。 |
| 人工清单 | 使用本目录UAT-ID；准备好小项目/说明，给操作步骤和可观察预期，避免要求用户创造复杂前置。 |
| 用户结果 | 保留用户原反馈；通过/失败/未测分别记，失败关联回归测试与修复T-ID。 |
| 下一步 | 只推荐下一批或阻塞处理；提交/推送/发布按该次用户明确授权执行。 |

一次人工验收覆盖同批多个子任务，减少切版本和准备样本的成本。返修只给失败项及必要邻接回归，不重发已通过全表；若底层共享改动确实扩大风险，说明追加检查原因。交付清单统一编号，避免“第3项”在换表后失去含义。
