## 3. 对回答中技术疑问的答复

### 3.1 Lane 目录和精确计数，不必每次打开都 O(N)

**源码确认：** 当前 `PresentationModels.ScheduleMidiTargetDiscovery` 存在 `QueryValues(0, long.MaxValue)` 全范围发现路径；`TimelineEventTargetIndex` 也有全源按 target 分组／建数组。现有实现不能直接被描述成已具备廉价的全 target 计数。

**可行方案（尚未实现／计时）：** 在导入／分页构建已经遍历数据时顺带建立 owner＋target 的摘要；编辑按命令最终结果维护 old／new 计数，碰撞覆盖、删除、Undo／Redo 都走同一正式事务。目录读取摘要，成本随 target 数 K 而非事件总数 N 增长，虚拟化展示。只有曲线或 Mapping owner、没有点的 target 也可显式标明来源，不强行编造点数。

旧项目首次缺摘要仍可能需要一次 O(N) 后台构建；期间显示“统计中”，可取消、不阻塞 UI、不把未知写成 0。普通刷新／打开目录不重复全量扫描，摘要不能常驻第二份完整事件对象数组。显隐入口已在 D-LANE01.g 确认：普通 Tab 可隐藏，右下箭头即全部目标目录，点击显示并激活；这不需要为了性能迫使用户保留所有 Tab。

### 3.2 琴键染色不能以读图像的一列替代音符时间语义

用户提出“读取播放位置 1px 的图像”可作为显示实验，但不能直接证明 Gate 正确：

- 水平缩小时一个像素可能覆盖多个 Tick；极短音符又会至少画成 1px，图像占据不等于 `[start,end)` 仍活动。
- 边框、抗锯齿、透明度、选择／预览和 Onion 层叠都会改变该像素；只扣除边框不能消除其他差异。
- 冷瓦片未就绪或旧内容正在替换时，音乐数据与当前图像可能暂时不同；不能据此让应该亮的键消失。
- MIDI Key 为 0～127，共 **128 个** 。即使只查每个 Key 一点，图像同步／读回成本也不能仅用“查128个点”估计。

建议使用正式范围索引派生每 Key 的有界占用／来源色摘要或增量端点游标，只查当前 Tick 附近，不扫描整工程；不从 bitmap 反推命中或音乐事实。该思路与 SRS §18.11.2／§18.11.3 及现有只读投影边界相容，具体成本要用冷／热页和多来源实测。维持已确认的 Gate、当前轨道颜色优先、最上层来源、不按 Mute／Solo 过滤；性能不合格则暂缓，不改成未批准的近似语义。

### 3.3 同目录文件并不消除剪贴板协议、生命周期和文件冲突

**源码确认：** 当前 `ProjectObjectClipboard` 仍依赖进程内 Session Identity／引用身份；主窗口向系统剪贴板写的是文本摘要，正式对象留在私有 clipboard；底层 storage lease 也不等于跨重启可发现的持久索引。

同 ProgramRoot 文件型方案可以避免大内容全驻内存，符合用户的空间位置要求，但仍需独立的完整性／长度校验、原子发布、有限内存、接收 lease、崩溃回收和磁盘不足处理。重新打开目录不代表某个半写文件就可安全粘贴。不同目录配置／剪贴板隔离也不意味着可以忽略两个安装位置同时打开同一项目文件的写入冲突；文件身份及已有可写会话保护必须按项目文件本身落实，不以安装目录代替文件身份。

D-MI06.a/b 已确认：单个持久当前槽，外部系统文本复制独立，完整快照＋current 索引置于 `<ProgramRoot>\Data\SharedClipboard`，准备文件在 `<ProgramRoot>\.tmp\SharedClipboard`。当前槽跨重启保留、不按年龄删；旧非当前项等待接收 lease 释放。原地升级按独立协议／数值契约／能力版本校验，不因 exe 版本改变就强制失效；不兼容明确拒绝、不自动删除未知文件。具体协议布局、预算、并发／故障测试尚未实施。

### 3.4 Q2 已消除的跨契约歧义

- **显示值与 Mapping：** D-VAL01.d 明确仅改变外侧编辑层及数值编辑工具。数据、Project Mapping Function、内置 Step、共享 accumulator 维持 raw 音乐语义。Help 必须举例：CC10 raw96 显示32，Batch `=p0*0.5` 得显示16／raw80；Mapping `value*0.5` 或 Multiply 0.5 仍得 raw48／显示−16。不将所有表达式当同一语义，也不擅自改 Mapping ABI。
- **删除 owner 与引用 owner：** D-STATE03.d 允许存活 A 保留被删 B 的少量 dormant 来源 ID 以支持音乐 Undo；B 自身 profile／Tab／缓存立即释放。该引用不持有 B 的对象、页、位图、任务或 lease，保存过滤悬空，关闭项目释放。与禁止保留已删 owner 自身状态不冲突。
- **主工具与子形态：** D-UI01.d 已明确保留共享 Draw；D-STATE03.e 引用的是这一最终划分，不是原推荐中两套主区／事件区工具。Track profile 保存共享主 ToolMode 和独立事件绘线形态；两个字段同 Track 同步，不同 Track 隔离，SubVoice 独立。
- **跟随范围与琴键染色：** D-VIS02.f 明确增加 Arrangement／Conductor 连续跟随；不使 R11 琴键染色扩大。其余尚未实现连续的已有 Follow 视图保留跳跃。已纳入本批的五类视图仍分别做性能门，不能借回退规则默默漏掉两类新增视图。
- **首次加载与粗细替换：** D-FX01.e 指定真正无缓存且尚未就绪时用静态棋盘；已就绪的空内容不显示永久等待。已有粗概览不加遮罩、粗→细不动画；首次空白→就绪独立动效仍受总开关和减少动画设置约束。仍不是近期实施项。

这些结论依据用户原答及静态源码／规格交叉检查；没有进行新的运行实验，不据此宣称延迟或内存预算已经达标。
