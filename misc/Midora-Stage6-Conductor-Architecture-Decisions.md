# 阶段 6 Conductor 架构决定

状态：依据已批准需求实施；2026-09-06。

## ADR-COND-01：分页正式集合与共享修订

Conductor 仍使用已有五种正式事件和 Stable ID；四种多项集合以不可变分页根及增量编辑表达，Project/编译修订快照共享根。可变 End Marker 单独冻结。禁止在 Project gate 内为百万事件逐条克隆记录，禁止逐项删除形成平方复杂度。编译和序列化只适配有序数据访问，不改变 wire 或 canonical 的值、排序及边界语义。

查询接口区分正式 ordinal、按 tick/ID 的有序查询及冷页准备。UI 不通过全量排序/字典构造完成一次可见区域请求。列表仅保留稀疏合并游标与有限可见行；文本按需格式化。

## ADR-COND-02：Tempo 与其他元事件分开投影、共享选择

Tempo 使用已有 Event Lane 交互状态机，增加阶梯保持呈现；其他四种类型显示为独立行。两者共享 absolute tick viewport、编辑指针、Project 选择身份及 Undo/Redo。Tempo 轴的显示范围与实际合法 BPM 范围分离，不强加经验型 BPM 上下限。

Tempo LOD 仅服务显示：每设备列保留首、末、最小、最大值，前驱状态进入左边界；密集点与标签数量受可见像素约束。完整记录始终通过正式源命中、选择及编辑。旧修订后台结果不得覆盖新修订，也不得在鼠标交互线程做整表扫描。

## ADR-COND-03：统一事件编辑事务

Tempo 的绘线、点移动/复制与既有 Properties、Clipboard、删除遵循同一正式碰撞规则。Tempo、Time Signature、Key Signature 同 tick 覆盖，Marker 不归并；tick 0 必需状态保持有效。批量准备、解析选择、排序归并及结果选择在现有资源有界事务中完成，发布一次 root swap，Undo/Redo 不重跑随机或表达式，也不逐项操作百万集合。

## ADR-COND-04：不扩大需求

本次不把通用 SMF Meta 提升为 Conductor 数据，不实现连续 Tempo ramp，不加入 Conductor Quantize/Batch Create，不改变 Project Format、音频链和已经验收的三种 Piano Roll 行为。新的控件和缓存只用于 Conductor 或明确共用的稳定接口；共享代码修改必须补回归。

## ADR-COND-05：小编辑与大编辑共用预算，但不强制同一页大小

准备事务已知最多 256 个候选时，Conductor 临时记录使用 64-record 页，避免一次 Marker 编辑为了少量数据创建多份 4096-record 缓冲。大任务和未知长度的惰性绘线仍使用既有 4096-record 页与统一 resident/spill 配额；该偏好限定在当前 preparation scope，不修改其他批量命令的默认页大小。大选区显式准备有界 ordinal 目录；小选择直接按 ID 查找，不先扫完整 Conductor。密集碰撞以排序归并处理，稀疏编辑保留局部查询。

## ADR-COND-06：拍号前缀缓存不是每条历史的永久副本

拍号到小节的派生映射按冻结拍号根与 TPQN 缓存。弱引用缓存避免每条 Undo 历史永久保留一份前缀数组；准备阶段通过全局最多一个未消费的 WarmLease 将新映射交给消费者。消费、新预热取代或对应 lease 释放后，强交接引用立即解除。lease 本身不持有 Project 或 map。

这里不声称拍号映射完全分页：真正的拍号变化仍需一次 O(N) 前缀计算和一个 O(N) Entry 数组；既有保存 JSON DTO、完整 canonical 编译产物也未在本阶段改为有界流式输出。预算报告中的 edit resident 上限不能当作整个进程的绝对内存上限。

## ADR-COND-07：首屏优先与取消冷命中回放

左侧列表每 256 行保留一个五路归并游标，后台构造目录；首个 256 行以内的可见窗口可直接读源，不等待百万行目录完成。每个编辑修订仍重建稀疏目录，但在后台运行，并取消旧请求；当前实现不是局部增量目录。列表只为可见行格式化文本和绘制高亮，拖动范围选择也在后台读取正式 ID。

冷页鼠标交互延迟到数据就绪后回放，保留起点、修饰键和自由线折线，而不是只保留最后坐标。新的物理按下、Escape、捕获丢失、选择/快照/视口/轴改变或卸载使旧请求失效；过期任务不得把旧选择重新发布到当前工作区。属性读取也在后台读取冻结快照，提交前检查 Project 与选择修订。
