## 需求追踪与边界

- 输入：同一修订的正式 Compiler diagnostics（含紧凑重叠 ranges），以及成功 MIDI 导出的 Warning / Info。
- 正式输出：诊断总数、严重程度统计和 ordinal 使用非负 Int64；逐条顺序、重复、来源、Error / Warning-as-error 判定保持不变。Full / Incremental 结果等价。
- 消费者：Canonical、失败异常、MIDI / Audio task result 使用显式 long-count 序列，不经 Int32 IReadOnlyList 伪装。WPF 使用独立有界窗口，筛选仍针对全源。状态栏总数不随筛选或页码变化。
- UI：筛选后数量不超过 Int32.MaxValue 时保留当前连续虚拟列表；超过时每页 4096 行，提供上一页、下一页和一基页码跳转。换页/换修订不得沿用旧行引用导航；页码输入错误不改变当前页。
- MIDI README：按既有确定性顺序最多写前 1000 条 Warning + Info；超出时在 Diagnostics 开头显示准确总数、展示数、省略数及软件内查看提示。仅文本展示截断，正式诊断不截断。冻结/准备/写入均不得为此展开完整逻辑序列。
- 超限：只在诊断逻辑计数累加入口产生专用、可辨别的友好异常；不得把任意算术 OverflowException 或系统内存不足误报为诊断计数超限。失败不发布半份结果，后台 Failed 与前台编译/消费提示保留准确原因。物理来源/range 仍受实际内存和集合容量限制，Int64 不等于无限资源。
- 归属：运行时诊断与窗口状态；不进入 Project、Undo、Modified、音乐 fingerprint 或 `.midora`。不变更产品版本/Project Format，不改音频及重叠语义。
- 依据：SRS §12.18～21、§14.15、§17.5、§20.9.7，INV-010/015/066；本次授权允许同步规格中的诊断容量、条件分页与 README 上限。
- 非目标：不生成数十亿真实对象来验收，不声称整个编译器任意源规模均为常量内存；不顺带实现此前审计记录的全局 F4 导航缺项，不改现有 Go to Source 行为。
